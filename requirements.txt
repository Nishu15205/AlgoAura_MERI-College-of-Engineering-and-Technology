# =============================================================================
# GlucoTwin — dependency manifest
# =============================================================================
#
# IMPORTANT — read this first.
#
# GlucoTwin was ORIGINALLY SPECCED as a Python / FastAPI backend serving a
# React / Vite single-page frontend. The live demo environment for the
# Happiest Health "Digital Twin Challenge 2026" exposes a single port (3000)
# and a single user-visible route ("/"), which a two-process Python + Vite
# stack cannot occupy. To preserve every functional requirement for the live
# demo, GlucoTwin is IMPLEMENTED AS A SINGLE Next.js 16 + TypeScript
# APPLICATION instead. Every required component has a 1:1 mapping:
#
#   FastAPI route handlers  -> Next.js Route Handlers (src/app/api/**/route.ts)
#   scikit-learn LogReg     -> src/lib/ml/logistic-regression.ts (from scratch)
#   xgboost / lightgbm GBDT -> src/lib/ml/gbdt.ts (from scratch, histogram + Newton)
#   shap TreeExplainer      -> GBDT.contributions() (Saabas, log-odds space)
#   pandas / numpy          -> src/lib/ml/features.ts + src/lib/ml/stats.ts
#   Synthetic data in Python-> src/lib/ml/data-generator.ts (fixed seed 20260117)
#   React / Vite SPA        -> Next.js App Router client components
#   Uvicorn / Gunicorn      -> Next.js dev server (port 3000)
#
# Because the runtime is Node/TypeScript, the AUTHORITATIVE dependency list is
# `package.json` (installed via `bun install`). This file is kept for two
# reasons:
#   1. It documents the original Python spec, so the project can be ported
#      back to FastAPI + React/Vite in a standard two-process environment
#      without re-deriving the dependency list.
#   2. It lists the key npm dependencies alongside, so a reader scanning
#      for "what does this project depend on" finds both stacks in one place.
#
# This is a research prototype on synthetic data. Not medical advice.
# =============================================================================
